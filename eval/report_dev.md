## 5. 3회 반복 (L02, L07, L13, L20, Y1)

- 판정이 3번 모두 같은 칸: **32/35 = 91.4%** (규칙 v1일 때 31/35 = 88.6%).
- 흔들린 칸: L02 제출물(다른 점을 찾지 못함 / 요약에 없음 / 요약에 없음), L20 생성형 AI(요약에 없음 / 원문에도 없음 ×2), Y1 시상(원문에도 없음 / 다른 점을 찾지 못함 / 원문에도 없음). 모두 '있느냐 없느냐'를 AI가 찾는 항목이다.
- 마감 값(출처별로 코드가 다시 읽은 날짜·시각)이 3번 모두 같은 공고: 4/5. **L07은 3번 중 1번 원문 마감으로 대회 전체 기간 끝(11/25)을 골랐다.** 이 회차는 규칙 v1에서 '다른 점을 찾지 못함'으로 끝났고, 규칙 v2(칸↔본문 모순 우선)부터 3번 모두 '불일치'가 됐다. AI의 날짜 고르기 자체가 흔들린다는 점은 그대로 남아 있다.
- 화면 값의 글자까지 3번 모두 같은 칸은 15/35 = 42.9%다. 'AI 요약' 칸의 짧은 설명 문장이 매번 조금씩 달라서다.
- temperature는 쓰지 못했다. Claude Haiku 5.5와 API 버전 2026-10-21(설치한 SDK 2.4.0의 기본값)은 temperature·top_p·top_k를 받지 않는다(보내면 400). 그래서 구조화 출력 + 코드 검증으로 흔들림을 줄이고, 흔들림은 이 3회 반복으로 잰다.

- 호출 **42회** (상한 100회): 근거 찾기 31회(스키마 오류 400 2회, 시험 1회, 본 표본 11회, 반복 10회, 보조 6회, 웹 화면 직접 확인 1회) + 비교군 ① 11회.
- 토큰 합계: 입력 271,200, 출력 164,256.
- 비용 추정: **약 $0.11** (Claude Haiku 5.5, 입력 $0.10·출력 $0.50 / 100만 토큰, 프롬프트 10만 토큰 이하 요율). 모든 호출은 `eval/api_calls.jsonl`에 토큰 수만 기록했다(키·본문 없음).
- 처음 2회는 7항목 × 3출처를 따로 정의한 출력 스키마가 너무 커서 400("compiled grammar is too large")이 났다. 스키마를 '항목·출처 행 목록' 하나로 바꿔 해결했다.

## 10. 해석할 때 주의할 점

1. **정답표가 AI 1차 판정이다.** 값이 다른 7건만 원문 재확인을 거쳤고, 사람이 전부 직접 확인하지는 않았다. 특히 '모호'·'요약에 없음' 칸은 기준이 흔들린다.
2. **표본이 작다.** 마감·자격 차이는 7칸뿐이다. 7/7은 "이번에 놓친 것이 없었다"는 뜻이지 성능 추정치가 아니다.
3. **규칙을 만든 작업과 채점한 작업이 같다.** 그래서 시험용 표본(11/9, `report_test.md`)은 도구를 보지 않은 별도 세션이 정답을 먼저 적고 엔진을 고정한 뒤 한 번만 돌렸다.
4. 비교군 ①은 같은 모델·같은 effort(low)로 물었다. 더 큰 모델이나 일반 챗봇 화면과는 다를 수 있다. 비교군 ①이 이번 표본에서 놓친 것은 1칸(L07)뿐이라, "찾은 수"로 도구가 크게 앞선다고 말하기 어렵다. 차이는 잘못 경고 수(0 대 4), 근거 인용 일치율(화면 100% 강제 대 76%), 7항목을 빠짐없이 같은 형식으로 본다는 점에 있다.
5. 원문은 한 페이지 HTML(또는 올린 PDF·HWPX)만 읽는다. 이미지·첨부 HWP·로그인 화면·자바스크립트 화면은 못 읽고, 그 경우 '확인 필요'나 '원문에도 없음'으로 나온다.
