# 01. 원문 확인 PoC를 처음 보는 사람을 위한 설명

## 먼저 이야기 하나

11월 4일, 공모전 포털의 KISTI 대회 페이지 위쪽에는 "접수기간 ~11.25, D-21"이 떠 있었습니다.
그런데 같은 페이지 아래 본문에는 "문제해결: 9. 15. ~ 11. 6."이라고 적혀 있었습니다. 11월 25일은 발표·시상 날이고,
결과물은 11월 6일까지 내야 했습니다. 위쪽 칸만 본 사람은 3주가 남았다고 생각했겠지만, 실제로는 이틀이 남아 있었습니다.

이 도구는 바로 이런 차이를 찾습니다. 사람이 하던 일을 그대로 옮기면 이렇습니다.

1. 포털 요약을 읽는다. (위쪽 칸, 본문)
2. 주최 측 원문을 읽는다.
3. 마감·자격·시상 같은 중요한 항목마다 "어디에 뭐라고 적혀 있나"를 찾는다.
4. 둘을 비교해 다르면 빨간 펜으로 표시한다.

이 중 3번(긴 글에서 해당 문장 찾기)만 AI에게 맡기고, 나머지는 코드가 합니다.

## 왜 AI에게 다 맡기지 않나

AI에게 "다른 점을 찾아 줘"라고 한 번 물어보면 꽤 잘 찾습니다(시험에서 7개 중 6개). 그런데 두 가지가 문제였습니다.

- **근거를 지어낼 수 있다.** 비교군 답에 나온 따옴표 문장 중 24%는 원문에 그대로 있는 문장이 아니었습니다(여러 줄을 합치거나 줄임표로 줄임).
- **매번 다르게 판단한다.** 같은 공고라도 어떤 때는 차이라고 하고 어떤 때는 아니라고 합니다. 이유를 설명하기도 어렵습니다.

그래서 역할을 나눴습니다. **AI = 문장 찾기, 코드 = 확인과 판정.**
AI가 찾아온 문장이 원문에 글자 그대로 없으면 코드가 버립니다. 그래서 화면에 나오는 근거는 100% 원문에 있는 문장입니다.

## 요청 한 건이 지나가는 길

사용자가 화면에서 링커리어 주소와 원문 주소를 넣고 [원문 확인]을 누르면:

```
[화면] web/static/app.js
   │  POST /api/check (요약 주소, 원문 주소 또는 파일)
   ▼
[서버] web/app.py
   │  ① 하루 호출 횟수 확인(전체·IP당)
   ▼
[요약 읽기] wonmun/pipeline.py → fetch.py → portals.py
   │  ② 링커리어 페이지 HTML을 한 번 받아, 안에 숨은 데이터(__NEXT_DATA__)에서
   │     위쪽 칸(접수기간·참여대상·시상규모)과 상세내용 본문을 따로 꺼냄
   ▼
[원문 읽기] fetch.py → textsrc.py
   │  ③ HTML이면 메뉴·스크립트를 빼고 글자만, PDF면 쪽 번호와 함께, HWPX면 압축을 풀어 문단별로
   │  ④ 줄마다 위치 번호를 붙임: 칸-3, 본문-12, 원문-p2-5 …
   ▼
[AI] wonmun/llm.py
   │  ⑤ 세 출처를 위치 번호와 함께 보내고, "7항목 × 출처마다 근거 문장을 글자 그대로 복사해
   │     JSON으로 달라"고 요청(형식은 JSON 스키마로 고정)
   ▼
[인용 검사] wonmun/quotes.py
   │  ⑥ 돌려받은 문장이 출처에 글자 그대로 있는지 확인(공백 차이만 허용). 없으면 버림
   ▼
[값 정리] wonmun/dates.py, money.py, judge.py
   │  ⑦ 남은 문장에서 날짜·시각을 정규식으로 다시 읽음 ("11. 7. 24:00" → 11월 7일 그날 끝)
   │     AI가 고른 날짜가 그 문장에 없으면 '확인 필요'
   ▼
[판정] wonmun/judge.py
   │  ⑧ 규칙표로 판정: 날짜가 다르면 불일치, 같은 날인데 원문은 17:00이고 요약엔 시각이 없으면 시각 누락 …
   │  ⑨ 원문이 없으면 같은 페이지의 위쪽 칸과 본문끼리 비교(1단계)
   ▼
[화면] 7항목 표: 요약 값(회색) / 원문 값(검정) / 판정(빨강·회색)
       행을 누르면 근거 문장이 원문 앞뒤 문맥 안에서 노랗게 표시됨
```

## 파일마다 하는 일과 이유

### wonmun/ (엔진)

| 파일 | 하는 일 | 왜 필요한가 |
|---|---|---|
| `__init__.py` | 7항목 이름 목록 | 모든 파일이 같은 항목 이름을 쓰게 |
| `config.py` | 모델 이름, 호출 제한, 키 파일 위치 같은 설정. 키 파일에서 키 한 줄만 읽음 | 키를 코드에 적지 않기 위해. 설정을 환경변수로 바꿀 수 있게 |
| `fetch.py` | 주소 하나를 한 번 읽음. 내부망 주소·15MB 넘는 파일은 막음 | 나중에 인터넷에 올렸을 때 서버가 내부망을 엿보는 데 쓰이지 않게(SSRF 방지). 봇 확인 화면은 우회하지 않음 |
| `textsrc.py` | HTML·PDF·HWPX·TXT에서 글자를 꺼내 줄 단위로 나누고 위치 번호를 붙임 | 위치 번호가 있어야 "이 문장이 원문 몇째 줄에 있다"고 보여 줄 수 있음 |
| `portals.py` | 링커리어: 위쪽 칸과 본문을 따로 꺼냄. 온통청년: 칸이 비어 있으면 붙여 넣기로 안내 | 11/4 조사에서 틀린 값 5건 중 4건이 '같은 페이지 안 칸 ↔ 본문' 차이였음 |
| `llm.py` | AI에게 근거 문장을 JSON으로 받음. 호출마다 토큰 수를 기록 | AI가 하는 일을 '찾기'로 좁히고, 비용을 셀 수 있게 |
| `quotes.py` | AI 인용이 출처에 글자 그대로 있는지 확인 | AI가 지어낸 문장이 화면에 나가지 않게 하는 마지막 문 |
| `dates.py` | "2026. 11. 06.(금) 11:00", "11월 30일(월) 17:00", "'26.11.5.∼11.19.", "~11.25", "자정까지" 같은 표현을 읽음 | 날짜 비교는 매번 같은 답이 나와야 해서 AI가 아니라 코드가 함 |
| `money.py` | "1,300만원", "1천만원"을 원 단위로. '상품권·현물' 낱말로 현금/현물 구분 | 시상 금액·현금 오인 판정 |
| `judge.py` | 값 정리 + 판정 규칙(설계서 2장) | 판정 이유를 사람에게 설명할 수 있게 |
| `pipeline.py` | 위 단계를 순서대로 부르고 결과 JSON을 만듦 | 화면과 시험 스크립트가 같은 흐름을 쓰게 |

### 판정 이름

| 판정 | 뜻 | 색 |
|---|---|---|
| 불일치 | 날짜·자격·금액이 서로 다름 | 빨강 |
| 시각 누락 | 같은 날인데 원문은 오전·오후 마감, 요약엔 시각이 없음 | 빨강 |
| 칸엔 없음·본문엔 있음 | 위쪽 칸엔 빠졌지만 같은 페이지 본문엔 있음 | 빨강 |
| 요약에 없음 | 원문에만 있는 조건(실격, AI 규정 등) | 빨강 |
| 다른 점을 찾지 못함 | 차이를 못 찾음. 같다는 보증은 아님 → "원문 확인 권장" | 회색 |
| 원문에도 없음 | 요약·원문 모두 그 내용이 없음 | 회색 |
| 확인 필요 | 근거를 원문에서 확인하지 못함(AI 인용이 원문에 없거나 날짜를 다시 못 읽음) | 연회색 |

### web/ (화면)

| 파일 | 하는 일 |
|---|---|
| `app.py` | FastAPI 서버. 예시 JSON 보내기, 직접 확인 요청 받기, 하루 호출 제한 |
| `static/index.html` | 화면 뼈대. 맨 위에 생성형 AI 사용 안내(인공지능기본법 제31조 ① 사전 고지) |
| `static/app.js` | 결과 표 그리기, 행 누르면 문맥 하이라이트, 포털 오류 신고 문장 만들기. 칸마다 'AI가 찾은 근거' 표시(제31조 ② 결과물 표시) |
| `static/style.css` | 색 규칙: 원문 검정, 요약 회색, 다른 곳 빨강, 확인 필요 연회색. 좁은 화면에서는 표를 카드로 |
| `examples/*.json` | 11/4 공고로 미리 돌린 결과 3건. 전화번호·전자우편은 같은 길이 *로 가림 |

### eval/ (시험)

| 파일 | 하는 일 |
|---|---|
| `cases.py` | 개발용 표본 목록, 뺀 이유, 원문 주소 |
| `fetch_sources.py` | 요약·원문을 받아 `data/dev_sources/`에 저장(git 제외) |
| `run_tool.py` | 저장한 원본으로 도구를 돌림. `--rescore`는 AI를 다시 부르지 않고 규칙만 다시 적용 |
| `baseline_chat.py` | 비교군 ①: 같은 모델에 "다른 점을 찾아 근거와 함께 알려 줘" 한 번 묻기 |
| `baseline_regex.py` | 비교군 ②: '접수기간' 줄의 마지막 날짜를 마감으로 읽는 정규식만 |
| `score.py` | 숫자 계산 → `metrics_dev.md` |
| `redact.py`, `make_examples.py` | 결과에서 연락처 가리기, 화면 예시 만들기 |
| `report_dev.md` | 결과 정리(좋은 숫자만 고르지 않고 그대로) |

## 해 보면서 배운 것

1. **AI 출력 형식을 너무 크게 정의하면 거절당한다.** 7항목 × 3출처를 따로 정의했더니 "문법이 너무 크다"는 400 오류가 났다. 같은 모양의 행 목록 하나로 바꾸니 됐다.
2. **AI는 날짜를 고를 때 흔들린다.** KISTI 공고에서 3번 중 1번은 대회 전체 기간 끝(11/25)을 마감으로 골랐다. 그래서 "같은 페이지 칸과 본문이 서로 다르면 원문 결과와 상관없이 빨강"이라는 규칙을 더했다.
3. **정규식만으로는 원문에서 마감 줄을 찾지 못하는 공고가 많다**(11건 중 4건). 대신 날짜를 '읽는' 일은 정규식이 AI보다 믿을 만하다. 그래서 찾기는 AI, 읽기는 정규식으로 나눴다.
4. **temperature 0을 쓸 수 없었다.** 지금 모델과 API 버전은 temperature를 받지 않는다. 결과가 흔들리는 정도는 같은 공고를 3번 돌려 쟀다(판정 91.4% 같음).
5. **많은 공고 원문이 글자로 읽히지 않는다.** 자바스크립트 화면, 이미지 포스터, 첨부 HWP. 이 PoC는 그런 경우 '확인 필요'로 솔직하게 둔다.
